Sunflower·英语陪同兼职 — 微信小程序源码
========================================

一、如何运行
1. 安装「微信开发者工具」（稳定版）并登录。
2. 打开工具 → 导入项目 → 目录选择本压缩包解压后的 sunflower 文件夹。
3. AppID 选择「测试号」，或填你自己的小程序 AppID。
4. 点击编译即可在模拟器中预览。

三、当前版本说明
1. 数据存在本机 storage，属于单机演示版；多人共享需要接入云数据库。
   utils/db.js 的接口（{ data, error } 形态）已按云端规范设计，替换实现即可上云，
   页面代码无需改动。
2. 支付为模拟流程：点击支付按钮直接改订单状态，不产生真实扣款。
   接入真实微信支付需商户号资质。
3. 定金 = 译员日报价 × 30%，在 pages/order-create 中自动计算。
4. 防重复预约：同一译员同一天只能有一个预约。商家筛选时自动隐藏当天已有
   生效订单（待接单/已接单/已付定金/待付尾款）的译员；提交预约和译员接单
   时都会再次复查（正式版由服务端最终裁决）。
5. 评价体系：订单完成后双方可互评（1-5 星 + 文字）。译员收到的评价展示在
   译员详情页与译员列表卡片（评分 + 条数）。
6. 订单管理：订单页支持状态筛选（全部 / 进行中 / 已完成 / 已取消）；取消与
   拒绝可填原因并记录在订单时间线；待接单、已接单未付定金的订单在服务日期
   过后自动取消；定金支付后双方可在订单详情看到对方联系方式（手机号可一键
   拨打，演示译员为脱敏号码）。
7. 服务地点：下单时可地图选点，订单详情与任务详情展示地点并可打开地图导航
   （演示订单已内置地点）。
8. 退款建模：定金已付后取消订单进入退款流程（退款处理中 → 约 8 秒后自动到账，
   时间线与完结文案同步更新）。正式版由微信支付退款接口驱动。
9. 站内通知：接单 / 拒绝 / 付款 / 取消等状态变动写入对方消息中心；订单页有
   未读红点与入口，消息中心支持全部已读、点击跳转订单详情（按身份过滤）。
10. 分享：首页与译员详情页支持转发给朋友 / 分享到朋友圈，分享译员卡片进入
    详情页默认预约明天。
11. 商家主页：译员在订单详情（定金支付后）可查看商家资料、公司介绍与收到的
    评价；演示商家内置 3 家。
12. 改期：商家可对待接单 / 已接单未付定金的订单申请改期（内联日期选择，校验
    译员新日期空闲与冲突），改期后回到待接单、译员重新确认，时间线记录改期。
13. 结算单：译员收入页新增可结算余额与「申请结算」，模拟到账（约 8 秒后自动
    完成并收到站内通知）；正式版接微信企业付款。
14. 收藏译员：商家可收藏 / 取消收藏译员（卡片红心），支持「只看收藏」筛选。
15. 演示数据自愈：演示译员的未来空闲日期过期后自动重建（用户自己的记录不受影响），
    商家端演示长期可玩；首页与订单页支持下拉刷新。
16. 技能双向匹配：译员资料需填写技能标签（场景/行业 16 个，至少 1 个才能保存）；
    商家首页可选需求技能筛选译员并按匹配度排序（显示百分比）；下单时选择订单
    所需技能；译员的任务大厅与任务详情显示订单与自己的技能匹配度 + 需求技能标签。
    匹配度 = 需求被满足比例（我的技能 ∩ 需求 / 需求数），订单需求为空不展示。

四、常见问题
· 首次进入需要填昵称并选择身份（译员 / 商家），之后可在首页顶部「切换身份」返回重选。
· 商家端筛选不到译员：确认所选日期有译员设置为空闲（内置演示译员未来 30 天均空闲）。
· 若要重新开始：删除小程序缓存（工具菜单 → 清缓存 → 清除数据缓存）。

五、接入云服务（规划）
1. 在 utils/cloud-config.js 填入 endpoint / publishableKey 并把 enabled 改为 true，
   utils/data.js 会自动切换到云端表访问（页面接口不变）。
2. 服务端建表 profiles / availability / orders / reviews（字段见 utils/data.js 的
   TABLE_COLUMNS），配置 RLS：行 owner 由 DEFAULT auth.uid() 写入，双方只能
   读写自己的数据。
3. 改造依赖本地实现的两页：pages/availability（rawList/saveAll 批量操作）、
   pages/profile-edit（直写 db.js 原始行）改为云端接口调用。
4. 身份迁移：session 的 'me' 改为 auth.uid()，演示数据改由服务端提供。
5. 登录接线：邮箱验证码组件（原 components/login-panel 已移除，可重建）或微信登录。
6. 服务端校验：订单状态机、接单日期冲突检测必须在服务端实现，前端校验仅作体验。
